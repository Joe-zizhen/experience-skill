# Myskills — 个人 AI agent skill 套件

六个独立插件，给会偷懒的执行器（Claude Code、Codex 等）用。可只用一个，可搭配。合起来能覆盖从想法到交付、验收、记经验，但**没有必须走完的全流程，也没有开机 skill**。

谁在什么场合用、定律原文、闭清单死因，以 [`contracts/suite-v1.yaml`](contracts/suite-v1.yaml) 为权威。本 README 是给人看的说明书，不是第二份规则。

---

## 1. 这是什么，不是什么

**是：** 一套「认人 + 闭清单」的工作插件。每个插件管一种不确定：还没想清要什么、代码该怎么写、根因还没定、事故要复盘、选项集被类比塌缩、付过的代价下次还要付。

**不是：**

- 不是一条流水线（想需求 → 设计 → 编码 → 复盘 → 记经验）。对得上谁就用谁，不必传棒。
- 不是第七个「开机 skill」。安装器写入宿主入口的是 [`contracts/boot.md`](contracts/boot.md)，只是进窗口的认人条。
- 不是提示词合集。每个插件都有「发生了还是假装」的闭定义：交得再完整，缺那几条仍算没做。
- 不是自动变聪明。定律默认执行器不可信，会把「看起来做完了」当目标。

---

## 2. 定律

**不可信执行器会把「看起来做完了」当目标。** 只许闭清单认形（不准估）、格子能核对、留下去的先问人、做成看现实。自评、散文充证据、没同意就写、没看见就声称完成——都算没做。

六个插件都是这条的推论。权威文本在 [`contracts/suite-v1.yaml`](contracts/suite-v1.yaml) 的 `law`。

几条立刻能用的推论：

| 推论 | 含义 |
| --- | --- |
| 认形只对闭清单 | 「感觉是小改 / 低风险 / 很明确了」不算定义。吃不准当更重的那档。 |
| 格子要能核对 | 硬门槛只要命令 + 命中/未命中。散文填满格子无效。 |
| 留下去的先问人 | 装东西、改配置、播种、删数据：先问。 |
| 做成看现实 | 文档写完、测试变绿、十一段空心作业，都不算完成。 |
| 认错就换 | 证据表明该换插件：停下，说出证据，换一个。信封可选。 |
| 闭清单会被事故推翻 | 真实事故证明按清单会判错 → 改清单，用户拍板。不准写「这次特殊」。 |
| 存储不是经验 | 文件躺在磁盘上、不进当前窗口，等于没有。 |

---

## 3. 怎么认人

安装后，宿主入口（Claude Code 的 `~/.claude/CLAUDE.md`，Codex / `.agents` 的 `AGENTS.md`）里会有开机卡。它只做一件事：这一单对得上谁，就用谁。

| 你的情况 | 用哪个 |
| --- | --- |
| 还在想要什么、要写需求或任务书 | `pm` |
| 已经在写、改、审代码 | `senior-engineer` |
| 坏了、测不过、行为不对，根因还没定 | `systematic-debugging` |
| 事故、多因、要复盘或交接 | `5w-ledger-v1-3` |
| 选项集像是被类比塌缩、假设一变答案就变、或明确要第一性原理 | `first-principle-v2` |
| 项目入口已挂短契约 | `experience` 在后台只读检索；不要把它当开工仪式 |

**仅难回头、仅「重大」不够。** 那只说明该想清楚，不说明该用第一性原理。需求不清仍走 `pm`；根因未定仍走 `systematic-debugging`；已经决定了只是写代码走 `senior-engineer`。

同一时刻一个主插件即可，不要六个一起把窗口塞满。只读经验检索不算主驱动。

用错了：停下，说出证据，换一个。只有真要把上下文交给另一个 skill 时，才写交接信封。单独用不必写。

## 4. 规则四级

全套规则分四级，由 `contracts/suite-v1.yaml` 定义，`tools/check-suite.py` 静态守卫。绝对化词语（必须 / 禁止 / 无豁免 / MUST / NEVER 等）只许活在 **[INV]** 章节。

| 级 | 含义 |
| --- | --- |
| **[INV]** | 不变量。违反即缺陷，无豁免。 |
| **[DEFAULT]** | 默认策略。项目事实或用户要求可覆盖，覆盖写在明处。 |
| **[HEURISTIC]** | 审查信号。只触发复核，不定罪。数值不是判决。 |
| **[EXAMPLE]** | 示例。无规范效力。只管所在那一行，不改后面整节的档。 |

## 5. 六个插件

### 5.1 `pm` — 你出想法，它出需求与任务书

**痛点：** 想法直接开工方向就错；AI 围着技术栈连问六句，功能边界一个不问；满嘴术语听不懂；散文需求让执行 agent 自由发挥。

**角色：** 你是领导（出想法、拍板）。它是产品经理（调研、反问、写文档、验收）。下游执行者拿任务书独立跑完——它把任务书当唯一真理，写错的事实 100% 被执行。

**核心：**

- **对人只说大白话。** 不准把「三型 / 直通 / 六维 / INV」念给领导听。领导听不懂的点头不算拍板。规格和任务书给执行者看，可以专业。
- **三型分流 + 能否直通。** 模糊痛点 / 成形想法走带路链。明确需求且直通四条全否，才直通规格。不准用「低风险 / 感觉能直通」当定义。
- **直通四条（中一条就不能直通）：** ① 数据放哪 / 删除 / 花钱 / 权限 / 破坏现有数据还没拍板；② 请求里有多件都能单独做完的事；③ 新的对外约定（接口、协议、别人会按这个依赖的行为）；④ 没有可判定的验收。
- **带路链（不直通主路）：** 愿望 → 为什么 → 因果 → 怎样算做成 → 不做什么 → 漏点。六维是地图不是问卷。主路不问怎么实现、用什么技术。
- **钢人关卡（写规格前）：** 重述真正要解决的问题 → 支持与反对各给最强论证 → 点出分歧和会改结论的变量 → 只问一个最关键的问题。你答完再给判断。直通跳过。
- **三份工件：** 概念版（≤1 页，你拍板用）、落地规格（验收 + 明确不做的 + 状态与约定）、任务书（投给执行 agent 的可执行信封）。执行型任务书不许砍：地界、明确不做的、验收命令、开工先读的地图路径。
- **替拍负面清单：** 数据存放位置、删除语义、花钱、权限、破坏现有数据——不许替你拍。

**怎么用：** 「我有个想法」「帮我写个 PRD」「写个任务书给 agent」。

**边界：** 不做技术方案深设计。选项集被类比塌缩时交给 `first-principle-v2`。bug 走 `systematic-debugging`。

### 5.2 `senior-engineer` — 编码行为

**痛点：** 打补丁式修复、不追根因、不管全局、重复造轮子、自审自夸、测试造假绿灯。

**是什么：** 分级的编码行为规则。它逼近高工在「写 / 改 / 审代码」时的核心判断，不模拟资深的全天工作。

**核心：**

- **先对大改闭清单认形，不准自己估「这算小还是大」。** 中一条就是大改；一条都对不上、并且把「对不上」用搜索写出来，才是小改。吃不准当大改。
- **大改八条（中一条即是）：** 对外接口、怎么存数据、谁能干什么、钱、对外配置、新第三方库 / 准备入库的公用能力、打中接口文档或契约测试、别人不传参就吃你改的默认值。
- **编码不变量：** 默认过滤必须签名旁披露；注释只写实测行为；替代数据带来源标记；永久修复必须先有因果解释（可逆止血可先上，但止血 ≠ 修复）；交付必须完整且已验证；测试证据不许造假；禁止抄官方库源码。
- **行为默认：** 先定根因（修 bug 走 `systematic-debugging`）；先说清波及面；最小改动；像周围代码；失败路径也是代码。
- **审查信号不是判决：** 600 行、兜底两层、20 行自写成本、两个调用方、5 文件改动面——只触发复核。
- **对抗性审查：** 实质改动交付前必做；首选独立子代理（只给 diff、规范、验收口径）。
- **显式 setup：** 写项目路由、装 MCP 等，只在你明确要求并同意后执行。

**怎么用：** 任何写 / 改 / 审代码的任务。你说「这次不用 / 本轮关闭」则整份本轮不执行。项目 `CODING.md` 可落地这套规则——skill 不在场时项目照样自洽。

### 5.3 `systematic-debugging` — 修 bug 的方法论

**痛点：** 随机乱试、一次糊多个改动、猜根因、同一个地方修了三次还在坏、紧急事故里把止血当成修好了。

**目标不是「找到终极根因」，而是取得足以选择修复边界的最小充分因果解释。** 无法控制上游时，在最早的可控边界修复也是合法答案，但边界要点名。

**核心：**

- **铁律：** 没有足以选择修复边界的因果解释，不做永久修复。
- **止血例外：** 活跃事故中，可逆、可观测、可快速回滚的止血（回滚 / 关开关 / 切流 / 隔离）可以先上。把止血当修复交付，视同违反铁律。
- **四阶段：** 因果调查（读全报错、固定复现、查最近变更、插桩、数据流回溯）→ 模式分析 → 假设验证（单假设、最小变更；正确修复可以原子性跨多个文件）→ 实施（失败测试优先）。
- **3 次失败 → 复核问题模型**（假设、观测、多个独立缺陷、架构都是候选），不宣判架构错误。
- 附件：根因回溯、边界化防御纵深、条件等待、`isolate-polluter.sh` 顺序隔离器。

**怎么用：** 出 bug、测试挂了、行为不对时用。日常局部 bug 不要上 `5w-ledger-v1-3`。查着查着发现是「该不该做」没定：停下，换 `pm`。

### 5.4 `5w-ledger-v1-3` — 事故级根因分析

**痛点：** 重大故障后说不清根因、复盘拍脑袋、多因交织被简化成错误故事、交接时因果链经不起追问。

**是什么：** 证据驱动的 Five Whys。每个因果环节先过证据准入台账，最终报告只能用 ADMIT 过的证据搭出来。

**核心：**

- **台账三值：** ADMIT（证据支持该环节）/ REFUTED（证据反驳）/ UNRESOLVED（证据不足，开放的边界）。
- **证据来源类型：** 用户陈述 / 闭合叙事 / 代码 / 日志 / 复现 / 外部文档。未实测的数字保持 UNKNOWN。
- **现有证据 vs 生成证据：** 读日志、读代码、看 git 仍是现有证据。只有你控制下跑出来的复现 / 插桩 / 单变量实验，才是生成证据。`confirmed` 仍要能把机制挂上生成证据。
- **多因：** 给最小充分因果集，不编一个单因故事。置信度全文不超过最弱一环。

**怎么用：** 高危事故、跨时间窗故障、多因交织、审计复盘、交接。日常局部 bug 不要用它。带着复盘去设计时，猜想和未证实的环节先当假设，不当事实。

### 5.5 `first-principle-v2` — 第一性原理

**痛点：** 凭惯性抄方案（别人都这样、过去一直这样、听起来像好架构）；把候选方案当对象来拆（给微服务做物理）；填满章节就声称「用了第一性原理」。

**第一性原理是一种思考，不是一种文档格式。** 按标题填空、把旧方案用推导的口气重说一遍、把句子分成四类交差，都不是它。默认产出是设计或决策，不是代码。没有你的授权，不准实现。

**何时用：** 当前选项集像是被类比塌缩、假设一变答案就变、或你明确要。仅难回头、仅「重大」不够。未命中触发而套用本格式 = 假装。

**引擎：** 钉对象 → 拆开对象 → 独立评估零件 → 找出缺口 → 再组装。顺序可循环：切错、尺不对、缺口打偏，必须回到对应步。

| 步 | 做什么 | 常见假装 |
| --- | --- | --- |
| 钉对象 | 对象是目标所依附的**事或物**，不是桌上那些候选方案。事：谁、在什么场合、对象上发生了什么事实。物：不靠做法词也能指出的那件东西（电池、一笔钱、一份记录）。 | 把平台 / 中台 / 微服务 / 框架当对象来拆 = 给类比做物理 |
| 点名类比基线 | 当前默认答案从哪来（竞品、旧设计、整包市价、行业惯例、用户原话），有则给可核对来源，没有写「无旧方案」 | 用户确认一种做法仍是主张，不是事实 |
| 拆开对象 | 拆成构成或可独立测量的性质。去掉当前方案的模块名，零件仍能被命名和评估 | 按架构图接缝假拆；另造一张零件分类表交差 |
| 独立评估 | 不靠现成方案，事实允许它是什么、必须是什么。尺子必须能量出数或真假：物理/逻辑约束、合同、可重复测量、零件本身的公开要素价 | 用「好架构 / 更清晰 / 可扩展」、行业基准、整包报价、近邻代理（打开次数当「已知」）当尺子 |
| 缺口 | 可核对的差（量、价、约束违反、目标做不到），不是「不够优雅」 | 为了有缺口而编差 |
| 再组装 | 从事实、可假的目标、约束重组。被迫必须指向已有来源或已测读数。没有任何一步的唯一理由是类比 | 只改了自由选择的变体，却当成第二条路径 |
| 验证第一步 | 必须打在缺口声称的那个差上，必须可能失败，写清测什么量、落在哪一边提案死 | 打满意度 / 转化率，而差不在那些量上 |

程度词（实时、高可用、简单、智能）必须落成可测的量，否则标未知。没测过的量标未知；未知的零件不算已评估。现有代码是约束（改它的成本），不是零件必须按现有模块存在的理由。

**发生了，当且仅当同时成立：** 对象检验通过；假拆 / 假尺 / 假验证检验通过；有真实缺口或写明重合原因；没有一步只靠类比；会改答案的事实有来源否则标未知；能指出新路径少哪一块目标会坏。

推完不是验证完。没跑验证第一步之前只能叫提案。本 skill 自己也适用：没看见执行器因此停手假拆 / 假尺 / 假验证之前，不准声称「用了本 skill 就发生了第一性原理」。

旧版拆在 `references/` 里的约束分类、重写门槛、迁移分解等已经删掉。SKILL.md 就是完整引擎，不再靠附录凑章节。

### 5.6 `experience` — 外置大脑

**痛点：** agent 的记忆 = 当前会话，关掉就清零。上次掉的坑下次再掉。

**第一性原理：** agent 的记忆 = 当前上下文窗口。窗口外的一切对它不存在。所以「agent 拥有经验」只有一个物理含义——相关 token 在它做决策的那一刻位于窗口内。**存储不是经验，检索才是。**

**核心：**

- **轻量只读检索在后台。** 项目入口携带带 schema 版本的短契约。每任务按它读项目 `docs/experience/INDEX.md`（≤150 条全平铺）+ 有则读跨项目 `general.md` + grep 兜底。skill 本体不随每任务加载。
- **skill 本体只在四类时刻调用：** 写入条目、维护、显式检索、播种 / setup。不准当开工仪式。
- **命中（闭的）：** 总账行对上本任务 → 打开那一条 → 行动会改这次做法。只扫标题不算命中。
- **入库四问（缺一不收）：** 会重现、重导有代价、改变行动、写得出失效条件。「本次做了什么」是流水账，拒收。
- **人工闸门：** 入库、删除、冷藏全部要你确认。只读任务零写入。
- **冲突时代码 / 契约赢。** 条目不当场删，标疑似失效。
- **跨项目经验：** 有 `~/.experience/general.md`（或 `EXPERIENCE_DATA_DIR`）就读，没有就跳过、不建。新电脑不会自动出现旧电脑的内容。skill 安装目录只放规则，不放数据。
- **hook 可选：** SessionStart 自动注入只能经显式 setup 启用，不准暗装。

**怎么用：** 项目挂短契约后日常什么都不用做。踩坑超过约 10 分钟、发现难找入口、外部行为不符文档、被二次纠正同一事实时，agent 会当场起草条目请你确认。

## 6. 搭配、换插件、交接信封

六个都是独立插件。搭配不必走固定流水线。`contracts/suite-v1.yaml` 里有几条常见车道，只是地图不是问卷：

| 车道 | 常见顺序 |
| --- | --- |
| 需求不清 | `pm` → 选项集被类比塌缩时 `first-principle-v2` → `senior-engineer` |
| 技术故障 | `systematic-debugging` → `senior-engineer` |
| 严重事故 | 可逆止血 → 定位 / 5w 审计 → 必要时第一性原理 → 再编码 |

**回边（发现走错了）：**

- 排障做到一半，证据表明是需求没定 → `pm`
- 第一性原理发现缺运行证据 → `systematic-debugging`
- 实现中发现约束不成立 → `pm`
- 5w 因果无法确认 → 回到观测取证
- 经验条目与当前证据冲突 → 代码赢，条目标疑似失效

**交接信封（可选）：** 只有真要把上下文交给另一个 skill 时才写。十二格：看见了什么 / 本该怎样 / 怎么复现 / 证据 / 机制或猜想 / 把握 / 范围 / 没查清的 / 红线 / 怎样能推翻 / 谁拍板 / 最小可退的下一步。没有的字段写「无」。单独用、搭配用，都不强制传棒。

同一 skill 多处存在时：项目内嵌（`<项目>/skills/`）> 用户级（`~/.agents/skills` 等）。项目内嵌随仓库版本化，是团队事实。

项目里的 `docs/experience/` 不进本仓。那是各项目自己的经验数据。

## 8. 安装

新电脑只走这一条：克隆 → 安装器 → 重启宿主。

```bash
git clone https://github.com/Joe-zizhen/experience-skill.git ~/skills-collection
python ~/skills-collection/tools/install.py --source ~/skills-collection --host-dir ~/.agents/skills
```

| 宿主 | `--host-dir` | 开机卡写入 |
| --- | --- | --- |
| 通用 / Codex 的 `.agents` | `~/.agents/skills` | `~/.agents/AGENTS.md` |
| Claude Code | `~/.claude/skills` | `~/.claude/CLAUDE.md` |
| Codex | `~/.codex/skills` | `~/.codex/AGENTS.md` |

**装完重启宿主。** 技能清单是会话启动时加载的缓存，不重启看不见新 skill。

安装器会：把六个 skill 拷进宿主 skills 目录（暂存 → 校验 → 备份 → 原子替换 → 读回哈希），并把开机卡写入入口。失败回滚。`--skills` 可只装其中几个。`--verify-only` 只读回校验，不安装。`--dry-run` 只校验不改盘。

跨项目经验：有 `~/.experience/general.md`（或 `EXPERIENCE_DATA_DIR`）就读，没有就跳过、不建。

**项目内嵌（团队共享）：** 把要用的 skill 目录复制到项目根 `skills/`，并在 `AGENTS.md` / `CLAUDE.md` 写指针。这是给仓库钉版用的，不是新电脑的默认故事。

远程执行依赖禁止 `@latest`，必须固定版本。

## 9. 校验与暗卷

提交前跑：

```bash
python tools/check-suite.py
```

它检查：frontmatter（`name` 等于目录名、`description` ≤ 350 字符）、四级标签与绝对词越级、UTF-8 无 BOM、相对链接可达、LICENSE、`.sh` 语法、`openai.yaml` 结构、开机卡 / README / suite 是否写了定律。退出码 0 = 全过。

[`contracts/dark-cases.md`](contracts/dark-cases.md) 是给人当面考模型的暗卷，答案不准写进 skill 正文。纸面不算过。当前八题：该直通却带路、小改却问播种、只扫标题却报命中、把止血写成修好了、查着查着是需求错了、单独用却硬写信封、填满格子当完成、这次特殊。

## 10. 维护与发布

日常改活副本 `~/.agents/skills`。本机若用 junction / 符号链接把 `.claude/skills`、`.codex/skills` 指过去，改一处即可（删 junction 用 `cmd //c rmdir`，不要 `rm -rf`）。

发布：

```bash
bash tools/publish.sh
python tools/check-suite.py
git add -A && git commit && git push
```

`publish.sh` 只负责活副本 → 本仓并读回校验。commit + push 仍由人决定。

会改这台机器或这个仓库的事（装东西、改配置、播种、删数据）：先问。

## 11. 常见误用

| 误用 | 该怎样 |
| --- | --- |
| 把六个插件当流水线，每单都走一遍 | 对得上谁用谁 |
| 把 `experience` 当开工仪式 | 短契约后台检索；本体只在写入 / 维护 / 显式检索 / 播种时调用 |
| 仅因为「难回头 / 重大」就套第一性原理格式 | 看选项集是不是被类比塌缩；否则想清楚用 `pm`，写代码用 `senior-engineer` |
| 给微服务 / 平台做第一性原理 | 那是给类比做物理。先钉对象 |
| 填满格子 / 测试变绿就声称完成 | 做成看现实 |
| 闭清单判成大改，说这次特殊按小改走 | 不准自行例外；要改清单就问用户 |
| 单独用一个插件却写十二格信封 | 不必写 |
| 把整仓拷进 `~/.claude/skills` | 走安装器，只装六个目录 + 开机卡 |
