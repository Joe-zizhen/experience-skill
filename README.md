# Myskills — 个人 AI agent skill 集合

六个独立插件，可单用可搭配。合起来能覆盖从想法到交付、验收、记经验，但没有必须走完的全流程，也没有开机 skill。

全套规则分四级（`contracts/suite-v1.yaml` 定义，`tools/check-suite.py` 静态守卫）：**[INV]** 不变量（违反即缺陷，绝对化词语只许活在这里）、**[DEFAULT]** 默认策略（项目事实或用户要求可覆盖）、**[HEURISTIC]** 审查信号（只触发复核，不定罪）、**[EXAMPLE]** 示例。

## 全景：六个插件，不是一条流水线

六个 skill 各管一件事，**可单独用，可搭配用**。没有开机 skill，也没有必须接棒传棒的全流程。

谁在什么场合用，以 [`contracts/suite-v1.yaml`](contracts/suite-v1.yaml) 为准。安装器写入宿主入口的 [`contracts/boot.md`](contracts/boot.md) 只是认人条：对得上谁就用谁。经验检索是后台，不算主插件。

只有真要把上下文交给另一个 skill 时，才用得上交接信封。单独用不必写。

## 速览：什么情况用哪个

| 你的情况 | 用哪个 |
| --- | --- |
| 「我有个想法 / 帮我写个 PRD / 写个任务书给 agent」 | `pm` |
| 要写、改、审任何代码 | `senior-engineer` |
| 出了 bug、测试挂了、行为不对 | `systematic-debugging` |
| 高危事故、复盘、交接、多因交织的故障 | `5w-ledger-v1-3` |
| 重大、难逆、代价高的技术/架构决策 | `first-principle-v2` |
| 任何任务（经验检索在后台只读进行，防重复踩坑） | `experience` |

## 1. pm — 需求入口：你出想法，它出需求与任务书

**解决的痛点：** 想法直接开工方向就错；AI 讨论需求时钻牛角尖（围着技术栈连问六句，功能边界一个不问）；满嘴术语听不懂；散文需求让执行 agent 自由发挥。

**是什么：** 扮演产品经理 + 项目经理。你是领导（出想法、拍板），它是 PM（调研、反问、写文档、验收），把模糊想法挤成三份工件：概念版（≤1 页，你拍板用）、落地规格（验收+明确不做的+状态与约定）、任务书（投给执行 agent 的可执行信封）。对人只说大白话，不讲术语。

**核心机制：**

- **八条不变量 [INV]**：执行前必须有人拍板（明确需求且能直通时，请求本身就是拍板）；替拍负面清单（数据位置/删除语义/钱/权限/破坏数据）；任务书命令必须亲手跑过；判卷冻结+暗卷只抽公开约定；只读任务零写入、文档默认对话交付；执行型任务书不许砍地界/明确不做的/验收命令/地图路径；能否直通只对 4 条闭清单、不准自评；跟领导说话不用术语。
- **三型分流 + 能否直通**：模糊痛点/成形想法走带路链；明确需求且清单 4 条全否才直通规格。不准用「低风险 / 感觉能直通」当定义。
- **带路链（不直通主路）**：愿望 → 为什么 → 因果 → 怎样算做成 → 不做什么 → 漏点。六维是地图不是问卷。主路不问怎么实现、用什么技术。
- **钢人关卡（写规格前）**：重述真正要解决的问题 → 支持与反对各给最强论证 → 点出分歧和会改结论的变量 → 只问一个最关键的问题；你答完再给判断、理由和下一步。直通跳过。
- **语言规则**：对人只说大白话；规格和任务书给执行 agent 看，可以专业。编码纪律不抄写，任务书一行指针指向 `senior-engineer`。

**怎么用：** 跟 agent 说「我有个想法」「帮我写个 PRD」「写个任务书给 agent」即触发。

**边界：** 不做技术方案深设计（重大分叉移交 first-principle-v2）；死因自带——连续 3 次「执行完才发现方向错」降级为被动模板，2 个月零使用删除。

## 2. senior-engineer — 编码行为：让每一行按高工标准写

**解决的痛点：** AI 打补丁式修复、不追根因、不管全局、重复造轮子、自审自夸、测试造假绿灯。

**是什么：** 一套分级的编码行为规则——不变量管证据与安全，默认策略管日常行为，审查信号管数值气味。

**核心机制：**

- **七条编码不变量 [INV]**：默认过滤必须签名旁披露；注释只写实测行为；替代数据带来源标记且层间不丢；永久修复必须先有因果解释（止血例外：可逆止血可先上，但止血≠修复）；交付必须完整且已验证；测试证据不许造假（红绿反验只管新增/修改的测试、禁自证、防线实证）；禁止抄官方库源码。
- **六条行为默认策略 [DEFAULT]**：先定根因（修 bug 走 systematic-debugging）；先说清波及面；最小改动；像周围代码；失败路径也是代码；编码行尾保真（**项目契约优先**，未定义才默认 UTF-8 无 BOM）。
- **审查信号 [HEURISTIC]**：模块边界按职责与现有架构（600 行只是气味）；兜底两层→触发设计审查（不宣判重写）；20 行自写成本；两个调用方；5 文件改动面。数值只触发复核，不定罪。
- **复用检索按风险分级**：高风险动作（新依赖/通用能力/动契约）走完整五步留证据；低风险改动本地检查即可，不强制外网检索。能力目录（mymodules）只登记真实复用——**没有真实候选禁止创建通用模块壳**。
- **对抗性审查**：实质改动交付前必做；首选独立子代理（只给 diff、规范、验收口径三样）；三轴（规范/需求/安全）。
- **显式 setup**：写项目路由、装 Context7（固定版本、禁 @latest）等动作只在用户明确要求并同意后执行。

**怎么用：** 任何写/改/审代码的任务开始时调用。项目 `CODING.md` 可落地这套规则的项目内全文——skill 不在场时项目照样自洽。

## 3. experience — 外置大脑：让代价只付一次

**解决的痛点：** agent 的记忆 = 当前会话，关掉就清零——上次掉的坑下次再掉，你定过的约定全不记得。

**是什么：** 跨会话经验系统。核心认知：**存储不是经验，检索才是**——相关 token 在决策点位于上下文里，才叫"agent 拥有经验"。

**核心机制（A+ 版加载方式）：**

- **轻量只读检索在后台**：项目入口携带带 schema 版本的**短契约**（几行，不是整份 skill），每任务按它读项目 `docs/experience/INDEX.md`（≤150 条全平铺）+ 有则读跨项目 `general.md` + grep 兜底 + 决策点重扫。**skill 本体不随每任务加载**——只在写入、维护、显式检索、播种/setup 时调用；不准当开工仪式。
- **命中（闭的）**：总账行对上本任务 → 打开那一条 → 行动会改这次做法。只扫标题不算命中。首行 `[经验门禁]` 仅当短契约要求时才输出。
- **通用经验有家**：跨项目坑放 `EXPERIENCE_DATA_DIR`（没有则 `~/.experience/`）下的 `general.md`。**有文件就读，没有就跳过、不建**；skill 安装目录只放规则，不放数据。新电脑不会自动出现旧电脑的内容。
- **入库四问**（缺一不收）：会重现、重导有代价、改变行动、写得出失效条件。条目标：行动/依据/来源与置信度/适用范围/失效条件/记录。**入库、删除、冷藏全部要你确认**；只读任务零写入。
- **保鲜与规模**：每条带失效条件；定期+即时双时机自清洁；永不因未命中淘汰；≤150 全平铺、超过两阶段；死场景进冷藏区 grep 可达。系统死因看你能看见的事（同一坑二次踩 / 你嫌烦 / 你确认不用了），不看「两周零命中」。
- **hook（可选增强）**：SessionStart 自动注入，**只能经显式 setup 启用**；播种时、以及编码大改且已有总账时问一句装不装，不准暗装。先打项目总账，有余量再打跨项目。可信根白名单默认拒绝、realpath/符号链接校验、严格 UTF-8、16KB 截断、失败静默。

**怎么用：** 项目挂短契约后什么都不用做。踩坑超约 10 分钟、发现难找入口、外部行为不符文档、被二次纠正同一事实时，agent 会当场起草条目请你确认。

## 4. systematic-debugging — 修 bug 的方法论

**解决的痛点：** 随机乱试、一次糊多个改动、猜根因、同一个地方修了三次还在坏、紧急事故里不知道该先止血还是先查因。

**是什么：** 目标不是"找到终极根因"，而是**取得足以选择修复边界的最小充分因果解释**；无法控制上游时，在最早的可控边界修复也是合法答案。

**核心机制：**

- **铁律 [INV]**：没有足以选择修复边界的因果解释，不做永久修复。**止血例外**：活跃事故中，可逆、可观测、可快速回滚的止血（回滚/关开关/切流/隔离）可以先上——但把止血当修复交付视同违反铁律。
- **四阶段 [DEFAULT]**：因果调查（读全报错、固定复现、查最近变更、组件边界插桩、数据流回溯）→ 模式分析（找正常样例对比差异）→ 假设验证（单假设、最小变更；**正确修复可以原子性跨多个文件**）→ 实施（失败测试优先；自动测试不可行时允许可执行复现/监控/独立验证，写明原因）。
- **3 次失败 → 复核问题模型**（假设、观测、多个独立缺陷、架构都是候选），不宣判架构错误。
- **红旗清单 [HEURISTIC]**：「快速修一下」「应该是 X」这类念头是暂停复核的信号，不是判决。
- 附件：根因回溯、边界化防御纵深（只在信任/所有权/不可逆副作用三个边界设防，日志不是校验层）、条件等待（订阅优先、单调时钟、可取消、谓词异常必拒）、`isolate-polluter.sh` 顺序隔离器（失败关闭，带测试）。

**怎么用：** 出 bug 时用。senior-engineer 的行为策略已联动——任何「坏了/不符合预期」都会走到这里。

## 5. 5w-ledger-v1-3 — 事故级根因分析（证据台账版五个为什么）

**解决的痛点：** 重大故障后说不清根因、复盘拍脑袋、多因交织被简化成错误故事、交接时因果链经不起追问。

**是什么：** 证据驱动的 Five Whys。每个因果环节先过**证据准入台账**，最终报告只能用 ADMIT 过的证据搭出来。

**核心机制：** 台账决策三值语义明确——**ADMIT**（证据支持该环节）、**REFUTED**（证据反驳该说法）、**UNRESOLVED**（证据不足，开放的边界）；每条证据标来源类型（用户陈述/闭合叙事/代码/日志/复现/外部文档）；症状/触发/直接原因/促成原因/根因/控制缺口严格分类；多因交织给**最小充分因果集**；置信度逐级传播、全文不超过最弱一环；未实测的数字保持 UNKNOWN。

**输出契约：** 默认两段（`<ledger>`+`<final>`）；**你指定 JSON/Markdown 等格式时服从你的格式**（语义不变）；宿主强制前缀（如命中标记）不算违约。

**怎么用：** 高危事故、跨时间窗故障、多因交织、审计复盘、交接。**日常局部 bug 不要用它**——那是 systematic-debugging 的地盘。

## 6. first-principle-v2 — 重大决策的第一性原理设计

**解决的痛点：** 凭惯性抄方案、重大难逆决策拍脑袋、在错误假设上盖楼。

**是什么：** 从基础事实推导最简正解的设计流程。默认产出是设计/决策，不是代码；没有实施授权时停在设计边界 [INV]。

**核心机制：** 一句话定义目标 → 决策输入四分（实测事实/需求/约束/假设；约束再分可挑战的设计约束与当边界的增生约束）→ 挑战没证据的假设 → 分解到不可再分 → 从验证过的事实重建最简设计 → 旧组件先过补丁堆阈值 → 候选对比（含"不新增组件"选项）→ 可逆优先 + 验证计划 → 盲点扫描。**未实测的阈值与数字一律 UNKNOWN**，不生成看似精确的伪证。深挖内容拆在 `references/`（约束分类、重写门槛、迁移分解、模式招募、5W 交接），SKILL.md 只留骨架。

**怎么用：** 重大、难逆、假设未决的决策：架构选型、重写还是修补、引入重依赖、5W 复盘后的修复设计。常规任务不要过度调用。

## 安装

新电脑只走这一条：克隆 → 安装器 → 重启宿主。

```bash
git clone https://github.com/Joe-zizhen/experience-skill.git ~/skills-collection
python ~/skills-collection/tools/install.py --source ~/skills-collection --host-dir ~/.agents/skills
```

Claude Code 把 `--host-dir` 换成 `~/.claude/skills`，Codex 换成 `~/.codex/skills`。**装完重启宿主**——技能清单是会话启动时加载的缓存，不重启看不见新 skill。

安装器会：把六个 skill 拷进宿主 skills 目录，并把开机卡写入入口（`.claude/CLAUDE.md`，或 `.agents` / `.codex` 下的 `AGENTS.md`）。不要把整仓塞进 skills 文件夹。`--skills` 可只装其中几个。

跨项目经验：有 `~/.experience/general.md`（或 `EXPERIENCE_DATA_DIR`）就读，没有就跳过、不建。新电脑不会自动出现旧电脑的内容。

**项目内嵌（团队共享）**：把要用的 skill 目录复制到项目根 `skills/`，并在 `AGENTS.md`/`CLAUDE.md` 写指针。这是给仓库钉版用的，不是新电脑的默认故事。

## 维护者

日常改活副本 `~/.agents/skills`。本机若用 junction 把 `.claude/skills`、`.codex/skills` 指过去，改一处即可（删 junction 用 `cmd //c rmdir`，不要 `rm -rf`）。发布：`bash tools/publish.sh`，然后人工 commit + push。提交前跑 `python tools/check-suite.py`。谁在什么场合用，以 `contracts/suite-v1.yaml` 为准。项目里的 `docs/experience/` 不进本仓。
