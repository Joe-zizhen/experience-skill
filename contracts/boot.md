# 开机卡（不是一个 skill）

六个都是插件：`pm`、`senior-engineer`、`systematic-debugging`、`5w-ledger-v1-3`、`first-principle-v2`、`experience`。可只用一个，可搭配。没有「开机 skill」，也没有必须走完的流水线，也不必为了换插件而传棒。

这一单对得上谁，就用谁（不准用感觉硬套）：

- 还在想要什么、要写需求或任务书 → `pm`
- 已经在写、改、审代码 → `senior-engineer`
- 坏了、测不过、行为不对，根因还没定 → `systematic-debugging`
- 事故、多因、要复盘或交接 → `5w-ledger-v1-3`
- 难回头的设计、假设会改答案 → `first-principle-v2`

经验：项目入口有短契约就按它读；不要把 `experience` 当开工仪式。它是后台记忆，不是主流程的下一棒。

用错了：停下，说出证据，换一个。只有你真要把上下文交给另一个 skill 时，才写交接信封（看见了什么 / 本该怎样 / 怎么复现 / 证据 / 机制或猜想 / 把握 / 范围 / 没查清的 / 红线 / 怎样能推翻 / 谁拍板 / 最小可退的下一步；没有的写「无」）。单独用、搭配用，都不强制传棒。

会改这台机器或这个仓库的事（装东西、改配置、播种、删数据）：先问。

谁在什么场合用，以仓库 `contracts/suite-v1.yaml` 为准。本卡只是进窗口的认人条。
