# senior-engineer — 编码行为、复用治理与对抗性审查

本插件是套件定律的编码推论：先对大改闭清单认形，再填格子；散文不是证据；没看见不算完成。本 skill 约束不可信编码代理：按改动不确定开门，格子要命令+命中。它逼近高工在「写/改/审代码」时的核心思维与最小，不模拟资深的全天工作。每次编码默认走硬门槛；交不出证据就不算开过工。

规则分四级：**[INV]** 不变量（违反即缺陷——错误、安全问题、越权或证据失真，无豁免）；**[DEFAULT]** 默认策略（项目事实或用户要求可覆盖，覆盖写在明处）；**[HEURISTIC]** 审查信号（只触发复核，不定罪）；**[EXAMPLE]** 示例（无规范效力）。

分工：本 skill 管编码时的判断、复用、审查与证据；**experience** 管跨会话记忆。根因未定的排障先走 `systematic-debugging`。产品该不该做走 `pm`。难逆大设计走 `first-principle-v2`。接缝见末节。

**默认开启。** 用户说「这次不用 / 关掉 senior-engineer / 本轮关闭」则整份本轮不执行（含缺口询问），交付写明已关闭。项目里更硬的红线压过本 skill 的 DEFAULT；未关闭时 INV 仍有效。

勿再用「低风险 / 实质改动」当正式开关。先按「小改 / 大改」清单对号，再填后面的格子。A / B / C-lite 都是小改的写法；满配 C / D 都是大改的写法。C-lite 与满配 C 都是形状 C，不是第五形。

## 小改 / 大改 [INV]

**agent 不准自己估「这算小还是大」。** 先对大改清单；中一条就是大改。一条都对不上、并且把「对不上」用搜索写出来，才是小改。吃不准、清单里有一条说不清 → 当大改。一次任务里有一处大改，整单当大改（或用户同意拆成两单）。

禁止当定义用的词（用了就是没认形）：低风险、只改了一点、内部重构所以没事、影响可控、应该没人依赖、感觉是小改、改动面很小、只改了一个文件、看起来像文案。

### 大改（中一条即是）

1. 改了**对外接口**：HTTP / RPC / 事件消息；**本仓库或其他包/服务正在用的**公开导出（函数签名、类型、store 的对外状态/方法、路由、DTO）。「正在用」必须搜到引用；搜不到写未命中，不能猜。未导出的 helper、只被自己模板用的组件 props 不算。
2. 改了**怎么存数据**：表结构、字段含义、文件格式、缓存键。
3. 改了**谁能干什么**：登录、权限、token、角色。
4. 改了**钱**：价格、支付、订单、退款、余额。
5. 改了**对外配置**：环境变量、远程开关、文档里写过的配置项。组件里一个 `defaultXxx` 变量不算。
6. **加了新的第三方库 / 包**，或准备把这段做成跨模块公用能力入库。
7. 改动的字打中了**接口文档、对外 schema、或契约测试**（字段 / 权限 / 错误码 / 支付）。UI 文案断言和快照不算。
8. 别人**不传这个参数、吃的就是你改的默认值**（必须搜到省略调用；搜不到就写未命中，不能猜）。

### 小改（必须：上面 8 条全部否，且否的依据能搜）

小改包括：纯内部看不出的修补或新函数；以及人能看见、但只是文案 / 空态 / 提示 / 布局 / 未被别人依赖的默认值。

**改动面小不能降档。** 命中大改第 1（对外接口）、3（谁能干什么）、4（钱）、5（对外配置）任一，不论改了几行、几个文件，整单仍是大改，走满配 C。不准用「改动面很小」改判为小改或 C-lite。

标小改时，至少交出这几项的命中/未命中（命令+结果），缺一项不准标小改：

- 接口文档 / 对外 schema / 契约测试：未命中（或未改这些字）
- 新包 / 新依赖：未引入
- 若改了某个默认值：调用方省略该参数 → 未命中
- 若改了导出 / store / 路由 / DTO：本仓库其他文件的引用 → 未命中（或未改这些）

**[EXAMPLE] 小改：** 改按钮文案；改空状态提示；给纯内部 helper 加一行；重命名未导出的变量。  
**[EXAMPLE] 大改：** 改接口字段；改表结构；改登录/权限；改支付金额；加一个 npm/gradle 包；改环境变量；改了别人正在省略使用的默认超时；改了被其他页面读的 store / 路由 / 本仓库已有调用方的导出签名；只改一行的支付金额、权限判断或环境变量——仍是大改。

闭清单死因：真实事故证明这 8 条会判错 → 提出改清单，用户拍板。不准写「这次特殊」把感觉请回来。

### 对上之后做什么（skill 规定，不是 agent 发挥）

| 档 | 对应格子 | 对抗审查 | 问经验播种 / hook | 问 Context7 | 问把本 skill 拷进仓库 |
|---|---|---|---|---|---|
| **小改** | A / B / C-lite | 不开 | 不问 | 不问 | 不问 |
| **大改** | 满配 C；加新库或入库则 D | 必须另开子代理；开不了就明说这轮没审成 | 没账本则问播种；有账本、配置里搜不到 `inject-experience-index` 则问一句装 hook。两问合成一个问题 | 已经选定库、要查怎么调则问一句 | 不问。除非用户明确说「这个仓库要带走这份规矩」 |

**小改不准走（走了就是错）：** 五步复用、对抗审查（含子代理/三轴）、问播种 / hook / Context7 / 把本 skill 拷进仓库、显式 setup。小改只填 A / B / C-lite 格子。

**大改要走（就在后文，不准跳过再找别处）：** 满配格子；D 则五步；对抗审查专节；缺口表里该问的。开不了子代理就明说这轮没审成，不准写「已审查」。

本 skill 装在本机即可约束当前 agent。项目里没有副本，**照样按这份写**。不播种只表示这个项目没有踩坑账本，不表示可以不按高工思路写。

## 工作卡（先读这张）

开关只有「小改 / 大改」一张，见上表。形状表只负责填哪几格，不另当开关。小改走了不准走的项 = 错；大改跳过要走的项 = 错。

1. 先对清单，不准估。本单取最大档。改动面小不能把对外接口 / 钱 / 权限 / 对外配置降成小改。
2. 格子要命令+命中；散文不是证据。
3. 最小改动；失败路径与正常路径同写（无新增则写依据）。
4. 不许假绿、不许自证、不许把止血当修复。
5. 大改且是新子系统 / 新对外契约 / 吃不准边界 → 先问要不要设计。用户说直接写才填格子。
6. 非平凡改动要回答（不涉及写「无」）：拒绝了什么、跑两次/做到一半、信任边界、旧数据或旧调用方、坏了怎么被看见、放哪一层。
7. 项目更硬的红线压过本 skill 的 DEFAULT。

## 证据形状 [INV]

散文解释不是证据。**只有硬门槛表里的格子、以及已经打开的正交门上的格子，需要命令或搜索 + 命中/未命中。** 表外叙述（命名理由、取舍、下一步、工作卡第 6 条）不要求命令。

把「没查到」标成「完成」= 违反 INV 5。

**[EXAMPLE] 格子上不合格：**「影响面可控」「应该能过」「只改了内部逻辑」「为了不造轮子引入这个库」「日志没了所以修好了」「应该更快」「领域更清晰」。  
**[EXAMPLE] 格子上合格：**「波及面：仅一处展示文案；`rg "确定"` 命中 1 处，未命中测试/接口文档」；「经验 INDEX：不可用（不存在）；小改不问播种」；「名词：`rg -i parent` 命中现有类型，不新造」；「成本：未测（用户未要求快，且无循环 IO）」；「手跑：未跑（本环境无浏览器）」。

## 硬门槛（每次编码）

先认形，再开门。门只为它能消除的那种不确定而开。**同一道门全文只有这里这一句触发；** 复用节、审查节只许指针，不许另写一套定义。禁止用「跨文件」代替认形。**认形看本单最大形状**，不是按文件分别认；一处满配则整单满配，或用户同意拆成两单。

吃不准时：A 与 C-lite 之间选 C-lite；B 与 C 之间选 C；C-lite 与满配之间选满配；C 与 D 之间只有真正引入依赖或准备入库才选 D。

### 可观察（认形用，不是「能测到」）

- **可观察：** 不读源码，最终用户或已发布调用方能看出差异（文案、空态、错误信息、默认值、布局、交互）。可观察 = 至少 C-lite，不得标 A。
- **不可观察：** 仅内部实现，对外输出与已发布契约不变 → 才可以是 A。
- **错误信息：** 用户或调用方看到的算可观察；内部 log 不算，除非它已经是对外契约（文档化的日志格式、审计流）。

### 满配 C 触发

不要另写一套触发词。用上面的大改清单：

- 中 1–5、7、8 任一 → 满配 C
- 中 6（新库或入库）→ D；若同时还中 1–5/7/8，按 D 并叠加满配 C 的编码前格子
- 一条都没中 → 小改，再按可观察/有无新代码认 A / B / C-lite

「配置」两个字不要单独当触发词。组件内部默认值、文案、空态不是对外配置。

命中 UI 文案断言或快照 → 留在 C-lite（须改测试并跑过），**不**因此升满配。

| 形状 | 怎么认 | 编码前 | 复用 | 审查 | 必须带证据的格子 |
|---|---|---|---|---|---|
| **A 原地修补** | 不新增函数/文件；用户/调用方看不出差异；不改已发布契约 | 波及面一句；对本次改动的字面量 grep 一次 | 不开 | 不开 | 波及面（含该次 grep 的命中/未命中） |
| **B 局部新代码** | 新函数/文件/复制逻辑；用户/调用方看不出差异；不引入依赖 | A + 本地三步 | 本地三步 | 不开 | 波及面 + 三步标签 |
| **C-lite（仍是 C）** | 可观察，且无满配触发 | 调用方 grep + 失败路径（或「无新增失败路径」）+ 手跑或 `未跑（原因）` | 有新代码则本地三步，否则不开 | 不开，不跑三轴 | 上述每格 |
| **满配 C** | 满配触发任一成立 | 调用方与消费方、对称面、真实失败路径、回滚（见下） | 不走五步；有新代码则本地三步 | 开（独立子代理） | 上述每格 |
| **D 新依赖或新通用能力** | 引入包，或准备入库的共享能力 | 若同时改契约则叠加满配 C | 五步 + 评估表 | 开 | 五步每步的三种合法标签 |
| **关** | 用户本轮关闭 | 整份停 | — | — | 写明已关闭 |

**A 的一次 grep 是升级检测，不是仪式：** 字面量命中接口文档、对外 schema 或契约测试 → **升满配 C**。命中 UI 文案断言或快照 → 可观察则 C-lite，不得标 A。

C 与 D 同时成立（新依赖并且改契约）按 D 做，并叠加满配 C 的编码前格子。

**满配税，C-lite 明确豁免（写在表旁，执行者填表时必须看见）：**

- **红绿反验：** 仅满配 C/D，且本次真的新增/修改了契约测试。C-lite 无新契约测试则无此格。
- **回滚：** C-lite 写 `git revert`（或同等）即可。数据/钱/身份只出现在满配且碰到持久化/支付/权限/身份时：必须点名怎么恢复，不能只写 git revert；没有 flag 就写「无 flag（依据），回滚=…」。
- **对抗审查：** 仅满配 C/D + 独立子代理。C-lite 不跑三轴、不进「已审查」。开不了子代理的满配 C/D：不声称已审查，用户验收是唯一审查；三轴可当自检清单，但不进「已审查」格子。

**手跑（C-lite 格子）：** 看见行为，不是又一次 grep。页面给路径+步骤（或已有 e2e/命令）；接口给 curl/测试。环境跑不了（无浏览器、无预览、无测试夹具）→ `未跑（原因）`。用 grep 填这个格子 = 不合格。交付结论若写「已看过 UI / 已验证表现」，手跑格就不能是 `未跑`。不要把「必须打开页面」写成 INV。

### 成本门（正交，不改变 A/B/C/D）[DEFAULT]

不新增形状。吃不准是否打开时 **选关**——误开会逼出假优化和假数字。

**打开（满足任一）：** 用户要快 / 省 / 包体小 / 不卡；或本次在循环里增加 IO（请求、读盘、查库、下游调用）；或本次对无界集合做全量加载或全量渲染；或形状 D（依赖的体积与传递依赖走评估表，算本门已开）。

**关闭：** 纯 A 文案；无人要求且看不出成本面变化。关着时不要提「顺便优化」，不要加缓存、防抖、预加载、提前分页。

**格子（仅打开时）：** 测量命令 + 前后数字，或 `未测（原因）`。「应该更快」「O(n) 所以没问题」「影响可忽略」不合格。没测不等于程序错了，等于**不准声称已经快了**。不把本门升级成 INV，也不新增审查第四轴；满配 C/D 规范轴在本门打开时要看到这个格子。

### 缺口必问 [INV]

安装、播种、MCP——凡是会写入项目或宿主配置的动作：**缺了必须先问；未得到同意不得执行；未问就跳过视同漏做。** 禁止自己决定不装并且一声不吭。

**把本 skill 拷进项目不是缺口。** 默认不问、不拷；只有用户明确说「这个仓库要带走这份规矩」才走显式 setup。

同一任务多个缺口合成**一个问题**：缺什么、装了多什么、不装怎么降级。同一会话同一个缺口只问一次。

| 缺口 | 何时问 | 用户拒绝之后 |
|---|---|---|
| 经验库未播种（无 `docs/experience/INDEX.md`） | 仅**大改**（满配 C、D）编码前。小改（A / B / C-lite）只标 `不可用（INDEX 不存在）`，不问。中途升到大改时补问，不问 = INV 5 漏做 | 本任务不播种；交付写明已问过 |
| 经验 hook 未装（配置里无 `inject-experience-index`） | 仅大改，且项目**已有** `docs/experience/INDEX.md`。无 INDEX 时只走播种问，不单独问 hook。小改不问 | 本任务不装；交付写明已问过 |
| Context7 未配置 | 仅大改，且（形状 D，或已选定库、要查「怎么调」）时。小改不问 | 本任务走官方文档/本机内容，标 `不可用（用户本轮不装 Context7）` |
| 项目未接入本 skill（无入口指针、无项目副本） | **不问。** 用户明确说「这个仓库要带走这份规矩」才走显式 setup | 不拷文件、不改入口 |
| 空的 `mymodules` 壳 | **不问、不建**（无入库候选时创建 = 违反能力目录 INV） | — |

只读任务：不问、不提醒；用户说「装」之前仍零写入。问不是装。

用户说「这个项目永远不装 X」→ 写到**不依赖项目经验库**的地方后再准不再问：项目 `AGENTS.md` / `CLAUDE.md` 一行，或 `~/.experience/general.md`（仅当该数据目录已存在），或用户 memory。按 experience 规则起草时仍要用户确认。没有这些落点时，新会话在**大改**上还要再问。

同意安装后：先列出将改的文件和内容，再动手。细节见「显式 setup」。

### 两份 INDEX，不要当成同一份

| | 经验地图 | 能力目录 |
|---|---|---|
| 文件 | `docs/experience/INDEX.md` | `docs/mymodules/INDEX.md` |
| 管什么 | 以前付过代价、下次要换做法 | 可复用代码现在在哪、契约是什么 |
| 谁先读 | 文件在则编码前轻量读；播种问询仅大改 | 有新代码时（B，或 C-lite/满配 C 带新文件），以及 D |

冲突时代码/契约赢，经验不当场删。

**经验 INDEX：** 文件在 → 按短契约轻量读（命中行则打开条目，写代码前遵循；`[功能]` 命中再去能力目录核对）。文件不在 → `不可用（经验 INDEX 不存在）`；仅大改 **并且走缺口必问**。允许每个会话出现这一行标签；禁止把「文件不存在」写成检索失败综述；禁止为检索而播种。

**能力目录 INDEX：** 仅当本次有新代码（B，或 C-lite/满配带新文件）或 D。文件在 → 命中则读契约页和源码核实。文件不在 → `不可用（能力目录 INDEX 不存在）` 一行，不创建目录、不问「要不要建空壳」。

### 编码前（认形之后）

格子以形状表为准，下面只补表里没有的。小改不准走的项见对上之后表，走了就是错。

**若上下文已有交接信封：** 范围、红线、本该怎样以信封为准，不另编需求。

**所有未关闭的形状：** 碰经验 INDEX（见上）。问询只按缺口表。

**满配 C 或 D**，且新子系统 / 新对外契约 / 吃不准边界 → 先问要不要设计（`pm` / `first-principle-v2` / 项目 plan）。用户说直接写才填格子。C-lite 不要每次挑战「该不该做」。

**A：** 波及面含「动谁、谁调用、破不破契约」。grep 该升则改走 C-lite 或满配 C。

**B：** 本地三步每步只标 `完成（来源）／不可用（原因）／降级为本地检查（证据）`。新类型名 / 文件名 / 业务名词：2–3 组关键词搜现有叫法，能映射则不新造；未命中才新建并写「新概念（已搜，未命中）」。不写有界上下文 / 聚合 / 充血贫血。项目已有分层则按 DEFAULT 4 不刺穿。

**C-lite：** 回滚 = git revert（或同等）。有新函数 / 文件 / 复制逻辑则加本地三步。改名或拆类型做名词搜索。成本门若打开，编码前标开因，交付前补格子。

**满配 C：** 有对外数据 / 接口则列 producer / consumer 契约（字段、单位、默认值、错误语义）；没有则写「无对外契约（依据）」。改 producer 查 consumer，改写路径查读路径。对称面只列本次碰到的。回滚碰到持久化 / 支付 / 权限 / 身份时必须点名怎么恢复。有新代码则加本地三步。改名或拆类型同样做名词搜索。成本门若打开，编码前标开因，交付前补格子。

**D：** 若同时改契约，先做完满配 C 的格子，再走复用五步。

### 编码中

**A / B / C-lite：** 最小改动；无新增失败分支则写「无新增失败路径（依据）」；两行能完不用十行。新代码读得像周围的代码。任何拼接 SQL/HTML/路径/命令、任何来自用户的数据：先标信任边界再写（表外叙述即可）。

**满配 C / D：**

1. 一次变更只解决一个问题；不夹带无关重构、全文件格式化、顺手「统一风格」。
2. 失败路径与正常路径同时实现。资源谁申请谁释放，释放与申请同层可见。
3. D 的新依赖必须填评估表后再引入。
4. 每个新增校验/过滤/权限/边界守卫，配一条本该被它拦住的输入；做不到就删掉或改成能触发的写法。
5. 新 API 要有本次真实调用方，不提交孤立 API。

### 交付前

**A / B：** 结论带亲手跑过的、与改动匹配的命令和输出。审查按对上之后表。INV 不免。成本门若打开（少见），补测量或 `未测`。

**C-lite：** 手跑或 `未跑（原因）`；声称已看过 UI/已验证表现则手跑格不得为 `未跑`。若改了文案/快照测试，测试须改过并跑过（不是满配红绿反验）。审查按对上之后表。INV 不免。检查 diff：无无关改动、无半截占位符。

**满配 C / D：**

1. 构建/测试/与风险匹配的检查亲手跑过，输出实际看过。「应该能过」不是过。测试通过 ≠ 交付正确。
2. 新增或修改的**那条契约测试**做红绿反验：先绿 → 故意改期望或破坏实现变红 → 改回再绿。没红过的这条不算测试。
3. 期望值来自独立样例、固定 fixture、合同或独立 oracle，不用被测代码的同一算法/helper 自证。
4. 检查 diff：无无关改动、无半截占位符、无 "rest unchanged"。
5. 对抗审查按专节。开不了子代理则不声称已审查。回滚若声称可执行，命令或开关必须真实存在；钱/身份/权限/持久化的回滚须点名恢复方式。成本门若打开，规范轴必须看到测量或 `未测`；没人要求却加了缓存/防抖/预加载，按多做删除。
6. 一句人话：改了什么、怎么验证、怎么回滚。

## 编码不变量 [INV]

违反即缺陷，无豁免（本轮关闭本 skill 除外）。

**1 默认过滤必须在函数签名旁披露。** 读取类函数默认隐藏了数据（软删除、禁用、归档、时间窗），写明「默认隐藏什么」「怎么取全量」。不披露的后果是静默少数据。

**2 注释与 docstring 只描述实测成立的行为，并写 Why。** 写下「线程安全」「幂等」「自动重试」之前先有实测，拿不出就删。注释解释为什么存在、外部约束、取舍；不复述代码在干什么。过期注释比没有更坏。

**3 项目已有替代数据来源约定时，必须遵守且标记不在层间丢失。** mock、假数据、降级返回从产生到消费都必须可检查地标成替代数据。优先用项目已有约定（如 mock / `documented` / `confirmed`）。中间层不许摘掉。没有约定时不升本条：按 DEFAULT 10 用名称或注释前缀标出，禁止为了本条发明类型体系。

**4 永久修复必须先有足以选择修复边界的因果解释。** 拿不出复现步骤的根因只是假说。活跃事故中，可逆、可观测、可快速回滚的止血可以先于根因——止血不是修复，**把止血当修复交付视同违反本条**。同一处修多次仍没好 → 停手复核问题模型，与人一起定，不宣判架构错误。

**5 交付物必须完整且已验证。** 不留占位符和半截活；硬门槛格子里的结论有证据。散文不是证据。缺口该问未问 = 本条意义上的漏做。

**6 测试证据不许造假。** 不许用 skip、删测试、放宽断言、mock **被测对象本身**、`|| true`、降阈值制造绿灯。协作对象按项目测试惯例 mock——**[EXAMPLE]** 测入口模块时 mock 它的依赖可以；把被测模块自己 mock 掉再断言不可以。禁止自证测试。红绿反验见交付前，范围是新增或修改的那条契约测试，不是每一条用例。恒真守卫比没有守卫更坏；守卫注释只许描述实测能拦下的范围。

**7 禁止把官方库源码抄进来改。** 唯一例外是官方以 sample/codelab 发布的参考代码且保留许可证头。

## 行为默认策略 [DEFAULT]

项目事实或用户要求可以覆盖，覆盖留在明处。

**1 先定根因，再动手改。** 「坏了/不符合预期」时：已安装 `systematic-debugging` 则调用，否则按其要点手工做——读全报错 → 固定复现 → 多组件在边界插桩定位失效层 → 单假设最小验证。小 bug 可压缩步骤，复现与因果解释见 INV 4。改深层原因，不改表面症状。日志消失 ≠ 已修复；加一层 catch ≠ 根因已断。先重述代码问题再写补丁（「加个重试」其实是超时太短，这类不是 pm，是编码时的问题重述）。

**2 动手前说清波及面。** 见硬门槛编码前。说不出来就是代码没读够。

**3 最小改动。** 修 bug 不顺手清理无关代码，重构不顺手加功能，新功能不顺手优化老逻辑。三个相似的地方胜过一次过早抽象。改动超出最初判断时停下来重新评估。你制造的孤儿（因此 unused 的 import/变量/函数）要清；无关死代码只报告、不删除。每行改动都能追溯到本次请求。

**4 新代码读得像周围的代码。** 匹配周边命名、注释密度、结构惯例。新代码放进项目已有的那一层；没有分层就不要发明分层（不要凭空造 domain/infra/usecase 壳）。不假设库可用——先确认项目依赖它，再按项目既有用法写。

**5 失败路径也是代码。** 与硬门槛编码中合并执行。真实失败路径要写，不可能场景不写。

**6 文本文件编码与行尾——项目契约优先。** `.gitattributes` 与既有文件约定是权威；项目未定义时才默认 UTF-8 无 BOM、行尾 LF。改多字节字符文件优先局部替换。写完用 `git ls-files --eol` 这类命令确认，编辑器显示不算数。

**7 想清楚再动手。** 实现前显式声明假设；多种解读并列，不暗选；有更简单做法就说出来、该顶回就顶回；不清楚就停下来点名、先问。

非平凡改动还要回答下面这些（不涉及写「无」；表外叙述，不要求命令）。A 文案几乎全是「无」：

- **取舍：** 选了什么、拒绝了什么、一句原因。
- **部分失败：** 有写入/重试/并发时，跑两次、做到一半会怎样；不涉及就写「无」。
- **信任边界：** 不可信数据从哪进、在哪变成可信；拼接 SQL/HTML/路径/命令时要先答。
- **旧世界：** 改持久化/默认值/错误语义时，旧数据或旧调用方会怎样。
- **可观测：** 新失败路径下，下一任靠什么看见（已有日志/错误信息/测试即可，不强制新可观测栈）。
- **层归属：** 放进项目已有的那一层；没有分层就不要发明分层。

**8 先定可验证目标。** 「加校验」→「写非法输入的测试并让它通过」。多步任务每步带 verify。弱标准（「让它能跑」）只会返工。

**9 不写没人要的东西。** 不超出请求；不给只用一次的代码造抽象；不加没人要的灵活性；200 行能写成 50 行就重写。包括没人要求的性能优化（缓存、防抖、预加载、提前分页）和没人要求的领域层 / 实体壳 / 仓储壳。

**10 无来源约定时的替代数据。** 生产者用名称或注释前缀（mock / fake / fixture）标出。不要为了标记假数据而发明 `Mock<T>` / 来源枚举等类型体系。项目已有约定时走 INV 3。

## 审查信号 [HEURISTIC]

只触发复核，不是缺陷证据，不定罪。

**1 模块化。** 默认一个功能模块一个文件、跨模块只通过导包调用。边界按职责与现有架构划分，**不按行数切**。单文件约 600 行是气味：过线问「是不是两个职责」，是才拆。`xxx_1.py` / `xxx_2.py` 比长文件更糟。

**2 兜底计数。** 小问题打补丁、大问题换方案。同一处已有两层兜底还没兜住 → 触发设计审查，不宣判重写。

**3 自写成本。** 约 20 行能写清且引入依赖更贵 → 倾向本地实现（仍须记录被比较 API、成本事实和选择理由）。

**4 调用方数量。** 声称「两个以上位置需要」却数不出位置 → 还没到入库时候。

**5 改动面。** 修同一个根因时，改动**超出该栈一次正规改动的预期触点**（说不清预期时，约 5 个文件当信号）→ 高优先级复核：这是问题本身的形状，还是大改盖住没定准的根因？说不清即不合格。文件数不是审查触发器。

**6 小变更成本。** 约 100 行通常好审；约 1000 行通常过大；文件数和概念复杂度同样重要。一次变更多个问题、夹带无关重构、新 API 无调用方 → 复核是否该拆。

## 复用检索与能力目录 [DEFAULT]

**先查后写，证据先行。** 复用门与行为形正交：**本次新增函数/文件/复制逻辑 → 本地三步**（无论 A 以外的哪一档；纯 A 无新代码则不开）。**仅 D 走五步。** C-lite 与满配 C 都不走五步。栈相关装配见 [references/stack-recipes.md](references/stack-recipes.md)。

每步只标 `完成（来源）／不可用（原因）／降级为本地检查（证据）`。

**本地三步：** 能力目录 → grep 源码（2–3 组关键词，中英文都试）→ 已装依赖。有现成 API 就用，不自写。

**五步（形状 D）：**

1. **能力目录** `docs/mymodules/INDEX.md`（无则一行不可用，不创建）。
2. **grep 源码。**
3. **已有依赖。**
4. **外部方案——先分清要哪一种：** 选型发现（有没有库能实现 X）→ GitHub / web 搜索。用法查证（已选定库 X 怎么调）→ Context7 优先；未配置则走缺口必问，在用户拒绝或尚未回答前不得假装已查过官方用法。拒绝后兜底：官方文档站 → 本机安装内容。
5. **评估依赖 vs 本地实现，保存比较事实：**

| 要回答 | 问题 |
|---|---|
| 必要性 | 内部是否已有？本地是否十几行能写清？ |
| 调用点 | 几个确定位置需要？ |
| 维护 | 最近发布、维护者、issue 响应 |
| 兼容 | 语言/框架/OS/构建是否匹配 |
| 版本 | 是否钉死或有 lockfile |
| 传递依赖 | 多带进来多少 |
| 许可证 | 是否允许本项目使用与分发 |
| 安全 | 已知漏洞与响应 |
| 可移除 | 替换要改多少代码 |

五步均不命中且成本可接受时，显式决定：复用 / 扩展现有 / 引入依赖 / 新建，并附理由。

经验命中「记得有这个能力」之后，仍以能力目录（或源码）为当前真相。

### 能力目录（mymodules）：目录概念，不是默认模块

- `docs/mymodules/`（INDEX + CONFIG + entries）只登记**真实复用**的能力；代码落点由 CONFIG 的 `code_location` 指定，按栈配方与项目既有结构定，不预设名字。第一次入库若有两个以上合理落点，问用户一次并钉进 CONFIG，不要看见配方表就新建 `src/mymodules/`。
- **[INV] 没有真实入库候选时，禁止创建名为 `mymodules` 的通用模块壳，也不许问「要不要先建空目录」。**
- **入库三问（全「是」才许入库）：** 两个以上确定位置需要且行为相同；复用后调用方更清楚而不是更多隐藏规则；维护成本低于各调用方自写。
- **[INV] 业务专属代码禁止入能力目录。**
- **入库三步，缺一不可：** 代码落位 → 契约页（是什么/解决什么/何时用/何时别用/入口/示例/依赖）→ INDEX 加一行。完成后联动 experience 写功能经验。
- 项目文档必须自洽：**[INV] 禁止把 skill 指针当作规则唯一来源。** 入口指针允许；只有用户明确说要带走规矩之后，才按显式 setup 写入（禁止只挂裸指针、项目内没有全文）。

## 对抗性审查 [DEFAULT]

**仅满配 C 或 D。** A、B、C-lite 豁免；硬红线仍要过。不以「跨文件 / 单文件」决定是否审查。

- **对抗立场：** 默认这次交付是错的，工作是让错误现形。**要开独立子代理：** 主 agent 只给 diff 范围、项目规范来源路径、需求/验收口径；不给实现推理、自评和期望结论。
- **开不了子代理：** 不声称已审查；用户验收是唯一审查。三轴可当自检清单跑，**不进「已审查」格子**。不准写「降级：自审」冒充已审查。
- **三轴，满配审查时都不可省：** 规范轴（项目规范 + 本 skill，含 H5/H6）；需求轴（逐条对照，单列漏做和多做，多做未确认则移除）；安全轴（本次 diff 碰到的信任边界：注入、XSS、路径遍历、硬编码密钥、权限缺失；列不出则写「本次无新增信任边界（依据）」）。
- **审完怎么处置：** 违反 INV 的当场修；多做未确认的删除；拿不准的问用户，不替用户扩范围。
- 测试纪律见 INV 6。

## 与 experience skill 的连通性 [DEFAULT]

经验检索的完整规则以 experience skill 为权威。本 skill 只规定编码任务里**何时碰 INDEX、缺口如何问**，不把 experience 正文再抄一遍，也不在每任务加载 experience 本体。
