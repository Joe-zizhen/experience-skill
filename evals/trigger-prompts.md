# 正负触发提示集（description 路由的回归检查）

**用途**：skill 的 `description` 是唯一路由依据。改任何 description 后，用本清单逐条验证路由行为——正例必须触发目标 skill，负例必须**不**触发（应流向括号标注的 skill）。

**用法**：逐条开新会话投给宿主（或问当前路由 agent"这条该调哪个 skill"），核对结果与预期。任一不符 = 路由回归，先修 description 再发布。

**维护规则**：

- description 新增触发词 → 同步在本文件加正例。
- 发现两个 skill 抢同一条提示 → 先改 description 划界，再把该条钉进负例防回归。
- 语境敏感的条目在括号里写明边界。

---

## pm

**该触发：**

1. 我想做一个本地的知识库
2. 帮我写个 PRD：给 App 加个签到功能
3. 帮我整理一下需求，错题本要加个搜索
4. 写个任务书给 agent，让它自己跑完
5. 让 agent 自己跑这个项目

**不该触发：**

1. 这段代码帮我重构一下（→ senior-engineer：需求已明确到代码动作，直接编码任务）
2. 这个报错帮我看看（→ systematic-debugging）
3. 要不要把单体重写成微服务（→ first-principle-v2：重大难逆决策）

## senior-engineer

**该触发：**

1. 帮我给错题本加个 Retrofit 接口
2. 审查一下这次的 diff 再交付
3. 这个类塞了两个职责，帮我拆
4. 写个新工具前，先查下项目里有没有现成的
5. 这个 bug 的根因已经定了，帮我改代码（边界：根因未定 → 先 systematic-debugging）

**不该触发：**

1. 我有个想法，帮我理理需求（→ pm）
2. 这次事故帮我复盘根因（→ 5w-ledger-v1-2）
3. 记住这个坑（→ experience）

## experience

**该触发（写入类；读取门禁为每任务自动，不需提示）：**

1. 记住：这个项目打包前必须先设 GRADLE_USER_HOME
2. 这个坑搞了我一小时，记一下
3. 以后改错题本 UI 都先问我

**不该触发：**

1. 帮我写个备忘录功能（→ pm：功能性"记录"需求，最易撞）
2. 之前那个 bug 帮我修一下（→ systematic-debugging："记得" ≠ 经验写入）

## systematic-debugging

**该触发：**

1. 测试挂了帮我看看
2. 构建失败了，日志在这
3. 这个接口返回不对
4. 页面突然白屏（常规 bug 语境；事故级复盘 → 5w-ledger-v1-2）
5. 性能突然变慢，不知道哪耗的

**不该触发：**

1. 这次线上事故写个复盘报告给团队（→ 5w-ledger-v1-2）
2. 这个功能该怎么设计（→ pm / first-principle-v2）

## 5w-ledger-v1-2

**该触发：**

1. 这次故障帮我做根因分析，要可审计的证据链
2. 复盘上周的宕机，写个 postmortem
3. 这个事故要多方交接，因果链必须经得起追问

**不该触发：**

1. 这个按钮点了没反应（→ systematic-debugging：局部单因 bug）
2. 帮我解释这段代码为什么这样写（→ 普通问答）

## first-principle-v2

**该触发：**

1. 这个模块该重写还是继续修补
2. 要不要引入 XX 框架，从第一性原理帮我分析
3. 数据库选型，迁了很难回头

**不该触发：**

1. 帮我写个 PRD（→ pm）
2. 这个函数怎么优化（→ senior-engineer：常规编码）
