# excellence — 把开放任务从「不会错的中间值」推到优秀

> 套件第八个插件。开放性任务的卓越输出工作流：手动点名触发，强制走「定标 → 排平庸 → 发散 → 收敛 → 批评」五步，成品置顶、过程为附录。本 README 是给人看的说明书；规则权威是本目录的 `SKILL.md`，套件路由权威是 `contracts/suite-v1.yaml`。

## 它解决什么问题

随便问一个问题，大模型大概率给你一个「差不多的、不会错的」答案，而不是优秀的答案。在开放型任务上尤其明显：方案设计、架构权衡、文案、观点、规划——默认输出常常停在及格线以上、优秀线以下。

原因有两层：

1. **训练原理**：模型拟合人类文本的概率分布，生成时倾向走高概率路径——也就是海量文本里最常见的写法。最常见的写法通常不是最差的，也不是最好的。
2. **对齐削峰**：RLHF 的奖励模型偏好安全、不得罪人、四平八稳的回答，输出分布被进一步压向「平均好」（业内称 alignment tax）。Karpathy 的表述：基座模型是包含人类所有知识与疯狂的高维模拟器，日常对话的「AI 助手」只是对齐后切出的一小块。

实证研究也支持这个判断：对照实验发现，用 LLM 辅助创意写作后，不同人产出的内容在语义上显著更相似、多样性下降（[Homogenization Effects of LLMs on Human Creative Ideation](https://arxiv.org/abs/2402.01536)），且不同厂商模型之间的输出也在趋同（[We're Different, We're the Same](https://arxiv.org/abs/2501.19361)）。

这个插件的立场：**平庸是默认流程的产物——不设标准、一次生成、交差了事。换掉流程，就能换输出分布。**

## 原理：五步工作流

| 步骤 | 机制 | 对治的平庸来源 |
| --- | --- | --- |
| 1 定标 | 先写 3–7 条本题专属、可判定的优秀标准，标准未写出前不产候选 | 没有标准时模型只能对齐「普通好」 |
| 2 排平庸 | 列出最显而易见的 3 个答案宣布为禁区，要用就得论证 | 分布中心的高密度区 |
| 3 发散 | 至少 3 个本质不同方向的候选，含 1 个反直觉方向 | 同方向多写几版 = 高密度区重复采样 |
| 4 收敛 | 只对第 1 步的标准打分，给排序理由，允许合成 | 「综合来看」式和稀泥 |
| 5 批评 | 挑剔专家视角挑 3 个真毛病，修完才交付 | 一稿交差 |

外加四条硬约束：交付物附失效条件（答案可证伪）；成品置顶、过程压缩为附录（读者先拿到能用的东西）；外部事实不发散（事实缺口声明为假设，不靠编造）；用户给了范例时范例优先于流程。

## 什么时候用

- 方案设计、运营计划、架构权衡、技术选型、文案、宣传语、观点文章、规划等**无标准答案、质量有梯度**的任务；
- 手动点名才启动：说「用 excellence」「认真做」「好好写」「这题很重要」。

**什么时候不用**（skill 自带的闭清单）：事实问答、报错/修 bug、有明确指令的执行（「把 X 改成 Y」）、代码小改小补、要速答——发散用在闭任务上是幻觉放大器。

## 会带来什么结果

两轮 A/B 盲评（36 次生成、30 份盲评、6 类题型、每格 2 复本）的结果：

- 用了 skill 的输出对裸问输出：**12/12 全胜**（首轮 11/12）；
- 提升最大的维度：**立场与判断 +3.2、洞察深度 +2.6、原创避俗 +2.4**（10 分制均值差）；
- 代价集中在输出篇幅，第二轮修复后结构维度不再失血。

质的变化（评委判词高频出现）：无 skill 版是「优秀但标准的模板」；有 skill 版有「非表面的取舍链」「敢认账」「失效条件罕见」。一个标志性细节：裸问版交出的宣传语，恰好是 skill 版在禁区环节点名排除并论证淘汰的句子——分布中心答案被双侧同时验证。

## 证据是什么

实验设计：6 类开放题型（运营方案、增长计划、宣传语、架构设计、文案、观点）× 2 复本；生成端与评审端均为独立 agent；评审只看匿名 A/B 副本（标签随机），按 6 维 rubric（具体性 / 洞察 / 原创 / 结构 / 可用性 / 立场）打 1–10 分，不知道哪份用了 skill。

**第一轮（v1）**：11/12 胜。暴露两个漏洞——结构维度 −1.2（过程脚手架淹没成品），唯一败局是「400 字观点短文被五步过程埋掉」；另有 1 例虚构权益（写死「购书九折」未标注）。

**修复（v2）**：新增「成品置顶、过程为附录」硬约束 + 虚构事实审查信号。

**第二轮（v2 vs 裸问）**：12/12 全胜；v2 vs v1 直接对打 2 胜 2 负 2 平，但结构维度 +1.0，且在此前唯一输过的题型上两局全胜——修复精确命中靶点。

**局限（诚实声明）**：评委是同模型 LLM、每对 1 人、每格 n=2，结论是方向性的；题型均为商业写作；决策类任务（候选由现实给定）未验证；skill 输出的结构特征可能被评委认出，盲评不完全盲。

## 安装

随套件安装（只装本插件）：

```bash
git clone https://github.com/Joe-zizhen/experience-skill.git ~/skills-collection
python ~/skills-collection/tools/install.py --source ~/skills-collection --host-dir ~/.agents/skills --skills excellence
```

或手动：把 `excellence/` 目录拷进宿主 skills 目录（`~/.agents/skills/` 或 `~/.claude/skills/`），重启宿主。

## 文件与规则分级

- `SKILL.md`：规则本体。`[INV]` 违反即缺陷（10 条）；`[DEFAULT]` 可覆盖（6 条）；`[HEURISTIC]` 只触发复核（8 条）；`[EXAMPLE]` 无规范效力。
- `agents/openai.yaml`：宿主装配元数据；`allow_implicit_invocation: false`——只响应手动点名。
- 修订纪律：INV 的增改要附一个实测败局（任务、败因、证据）；HEURISTIC 的增改要说明误报成本。无证据不加条款。

## 边界（它不做什么）

- 不突破模型能力上限——它换流程，不换模型；
- 不替代你提供的领域背景与范例——给范例仍是已知最强的提质量杠杆；
- 自我批评抓不了事实性与领域专业级错误——过了批评环节不等于专业正确；
- 输出更长更慢是流程的固有成本，简单问题不要点名它。
