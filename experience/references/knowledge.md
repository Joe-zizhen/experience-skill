# 知识约定

## 内容与范围 [DEFAULT]

知识服务于后续理解、定位、判断和正确行动。常见内容是项目导航、约束与决策、可靠方法、机制与排查经验，以及明确的个人偏好；类型帮助阅读，不要求机械分类。

范围与存储位置分别处理：项目事实保留项目条件；跨项目成立的本机方法进入适用通用范围；真实共享约束连接同一来源。其他项目的方法先作为候选案例核对，再依据证据形成可迁移认识。

## 最小主题结构 [DEFAULT]

新主题采用扁平单行标量 frontmatter，必填 `id`、`scope`、`status`。复杂条件、别名和关系写正文；工具按明确的扁平约定解析。

```markdown
---
id: project-a/theme-resolution
scope: project:project-a
status: active
---

# 主题覆盖与定位入口

当前认识：已有结论，以及关键推断的身份。
适用条件：项目、环境、版本或任务条件。
如何使用：它支持哪一步判断或行动。
依据与入口：当前代码、测试、文档、明确决策或实测现场。
相关知识：目标标识、关系及连接依据。

## 必要现场
支持结论的原始细节；长材料按需读取。
```

`id` 至少有命名空间/主题两段，各段以小写 ASCII 字母或数字起始，其后可含小写字母、数字、点、下划线或短横线。`scope` 为 `general`、`project:<项目标识>` 或 `machine:<机器标识>`，标识采用相同单段字符约定。身份由明确 setup 或已有约定取得；文件移动保留知识 id。

简单知识用几行即可表达，复杂主题按关键结论分别说明来源和置信度。当前认识与短现场可在同页，长证据按需要链接。

## 证据怎样进入知识 [DEFAULT]

优先引用已有任务报告、提交、测试输出、日志、源码与契约。需要跨会话保留关键现场时，在已授权变更中保存最小可追溯片段，说明原来源、环境、操作、预期和实际结果。

独立证据可放在同知识区的 `evidence/`，使用明确 UTF-8 的 `.txt`、`.log` 或 `.json`；主题链接到材料，日常目录展示知识路由，复核时再打开现场。保留影响判断的上下文，敏感值按本体要求脱敏。

观察材料与行动结论分开管理。日志能够支持当时的观察；根因、一般方法和跨范围适用性需要进一步核验。证据不足时，主题表达已知事实、待核问题和下一步来源，而不伪装成已验证方法。

## 状态与证据身份 [INV]

- **active** 参与正常检索，采用前仍须核对本次条件。
- **needs-review** 提供带警示的定位线索。必须标出争议结论；采用前先完成本次核验，同页有依据的入口继续可用。
- **retired** 用于明确历史追溯，退出通常的当前行动候选。
- 发现冲突后必须立即限制本次采用；尚未写回状态不能成为继续无条件信任可疑内容的理由。
- 实测、源码、文档、用户陈述与推断必须分别标明；禁止伪造来源、因果或验证结果。
- 记录时间必须来自实际可核验时间；读取日期不能代替验证日期，失效条件不自动授权删除。

## 时间、版本与历史 [DEFAULT]

时效敏感的结论说明成立版本、环境或时段，并把证据取得/验证时间与该成立范围分开。只对受影响结论更新，不因为页面有一条变化就丢弃其他可靠内容。

多个版本仍被不同项目使用时，保留各自条件与来源，让当前问题取得适用版本。新信息与旧信息冲突时，核对来源可靠性、环境变化和期望；时间先后只是判断线索。

历史保留可用于解释旧决策、再次核验和后续归纳。退役、归档、降低取用优先级与永久删除分别处理；保存和删除都遵循本次授权。

## 归纳、主题与关联 [DEFAULT]

主题呈现可用认识，案例保存适用性的依据。比较成功做法、失败反馈与例外，形成有边界的归纳。新的证据可以修正结论，也可以修正条件、定位或使用方法，具体流程见[维护与巩固](maintenance.md)。

关系可表达依赖/影响、依据/验证、适用/实现、相似案例、修正/取代/例外：

- 同一知识维护主要版本，并由适用项目引用。
- 相似机制保留不同场景实例，用比较关系帮助区分条件。
- 跨项目关系保留范围和来源；实际访问依据当前授权。
- 内容变化后检查相关标题、别名、入向引用和邻近主题，保持取用路径与当前认识一致。

Markdown 相对链接连接同一知识区内的主题或证据。跨知识区引用使用稳定标识 `knowledge:<id>`，并说明所属范围与已授权来源位置；工具只检查它的结构或本地可达性。区外源码用“当前项目相对路径＋符号/行号”的代码字面量，外部文档可用明确 http(s) 来源，由宿主按授权核验。

## 索引与旧材料 [DEFAULT]

索引帮助定位主题：稳定标识、范围、主题/别名、典型任务说法和目标路径。例如：

```text
- project-a/theme-resolution｜project:project-a｜主题覆盖（颜色 / theme / 页面改色） → topics/theme-resolution.md
```

新旧资料并存时，合并尚未被索引覆盖的旧标题目录，按已明确的主要版本采用。legacy 表示尚未按新结构核验，内容是否有效仍看当前证据。旧卡中的行动、依据、范围和现场可逐主题映射。

## 判断例子 [EXAMPLE]

- 成功定位隐蔽主题覆盖链：核对来源后补充导航主题、适用页面与定位方法。
- 多次可靠操作有共同前提：比较条件和例外，形成可复用流程及验证办法。
- 后端问题尚待修复：任务状态跟随问题单，另评估昂贵发现的稳定边界或入口。
- 已有主题的结论被新证据纠正：沿用主题用途，说明修正依据和具体影响。
- 工具验证受阻：准确保存当前未完成部分；经过复现和替代路径验证后形成工具方法。
- 用户明确表达偏好：按其陈述身份与适用范围保存。

以上是场景示例，实际变化根据本体的分流与授权办理。相关研究机制和适配边界见[研究映射](research-basis.md)。
