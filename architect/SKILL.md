# architect — 架构师

本插件是套件定律的推论：系统怎么拆、这次改动落在哪，不进窗口等于没有。交付是结构，不是实现。底图只登记现状；意图只活在尚未落地的本单图纸。

规则分四级：**[INV]** 不变量（违反即缺陷，无豁免）；**[DEFAULT]** 默认策略（项目事实或用户要求可覆盖）；**[HEURISTIC]** 审查信号；**[EXAMPLE]** 示例。

编码任务不以本插件为主驱动。底图靠项目短契约进窗口（和经验同一机制）。用户要类图/时序/落点时，本插件才当主驱动。

## 硬规则 [INV]

1. **交付是结构。** 本单交付：模块/类型归属、本单类图（只画碰到或新造的）、本单时序（只画这次谁在什么时候调用谁）、对项目底图的补丁（若归属变了）。没有用户授权，禁止把设计当实现去改业务代码。
2. **底图写入、删除、冷藏必须经用户确认。** 起草可以；未同意禁止落盘、禁止改 `INDEX.md`、禁止偷改正文。
3. **代码与底图冲突：按代码执行。** 底图禁止当场偷改；标「疑似过时」并问。用户决策类（已拍的拆法）禁止进自动处理。
4. **未问、未同意，禁止改 INDEX。**
5. **底图只登记现状。** 禁止把「将来归谁」写进 INDEX。意图只活在尚未落地的本单图纸；代码合入后再补丁底图。
6. **底图海拔。** 现状底图：主模块和归属都在。禁止用全仓函数调用图当底图。本单图纸不到每个函数。
7. **格子能核对。** 本单类图每个点名的类型必须有搜索命中，或标「新造（已搜未命中）」。时序每个被调者必须能指出存在或标新造。INDEX 每一行必须有一个能搜到的符号。未交出这些格子，禁止请人点头。
8. **总账能数。** INDEX 模块行超过 40 则按域拆，总账只留域名。禁止一页全宇宙一次点头。播种分三批（见「播种三批」），每批最多 15 行且每行有搜索格子。skill 不准写死某项目名单。项目 INDEX 必须写从代码搜到的名字。
9. **没挂短契约则底图不会被自动读到。** 必须在交付里写明这一点，不准假装项目已经在用底图。
10. **命中要核符。** 打开某 INDEX 行时，必须对该行能搜的符号做搜索。搜不到则标「疑似过时」并问，禁止把死符号当活底图用。

## 何时出图纸 [DEFAULT]

会动模块归属、新类型、或跨块调用顺序 → 出本单图纸；归属变了则起草底图补丁。只改已有类型内部实现 → 读底图、不改底图。用户明确要类图/时序 → 出本单图纸。

## 底图 [DEFAULT]

家 = 每个项目的 `docs/architect/`。不进经验库，不进 skill 仓库，不进全局目录。

```
docs/architect/
  INDEX.md      # 总账：一行一个模块（现状）
  archive.md    # 冷藏（死模块）
  .last-clean   # 自清洁日期
  <域>.md       # 详情，命中才打开
```

**INDEX 是总账，不是细架构。** 细架构（拥有 + 进出边 + 不拥有）只活在详情文件。把调用顺序写进 INDEX = 假装。

**第一次（现状底图，不是意图）：** 已有代码走「播种三批」。还没代码：先出本单图纸（意图）；等有代码再登记底图。不准把设计图写进 INDEX 冒充现状。

**以后每一单：** 对着底图做本单类图和时序。意图与现状不同，写在本单图纸里，不改 INDEX。代码合入、搜索格子能打上之后，再交底图补丁。

## 检索 [DEFAULT]

存储不是约束，进窗口才是。

- 项目已挂短契约：每个任务开头扫 `INDEX.md` 索引行（编码任务不免除）。对上这次要动的模块 → 打开对应详情，并对该行符号做搜索。只扫标题、不打开 = 不算命中。命中 = 打开后会改变这次落点。
- 本插件主驱动时：读总账 + 打开本单相关块 + 交出搜索格子。
- 编码主驱动时：不切到本插件；短契约仍要扫 INDEX。
- 项目没有 `docs/architect/`：不建、不扫；用户明确要求启用才走播种。

## 自清洁怎么做 [DEFAULT]

真正防腐烂的是 INV 10：任务命中某行就搜该行符号。不靠 git hook，也不靠「记得 pull」。定期 pull 检查只是辅路径，跑不了就跳过。

1. 没有 `docs/architect/` → 跳过。
2. **即时（主路径）：** 打开 INDEX 行时搜该行符号。搜不到 → 候选「疑似过时」。
3. **定期（辅路径）：** 每天首次 `git pull` 后，用 pull 碰到的符号对 INDEX（约 3 分钟，写 `.last-clean`）。跑不了就跳过并写明，不准假装已清洁。
4. **问询：** 附证据和推荐（改 / 冷藏进 `archive.md` / 保留）。用户一句话裁决。未同意不动 INDEX。
5. 冷藏条目保持完整，grep 可达；模块复活时移回并恢复索引行。
6. 不装新 hook。经验那套 SessionStart 注入是另一条产品；底图靠短契约进窗口，靠 INV 10 核符。多一条 fail-open 钩子不会比短契约更真。

## 播种与 setup [DEFAULT]

会创建或修改项目文件。**[INV]** 只读任务禁止执行；未向用户明示将改的文件与内容并得到同意，禁止动手。默认不给任何项目播种。

1. 找入口（`AGENTS.md` / `CLAUDE.md` / 等效）。一个都没有时，只建 `docs/architect/`，并说明需要手挂短契约，否则总账不会被读到。
2. 建 `docs/architect/INDEX.md`（用下方总账模板）和空的 `archive.md`。
3. 按「播种三批」起草现状底图。每批 ≤15 行，每行一个能搜到的符号，用户点头后再写入详情并登记 INDEX。
4. 入口挂下方短契约（schema 1）。
5. 告知：底图已建或需手挂、从下个任务起生效。编码任务仍走项目已有编码插件；底图靠短契约，不切主驱动。

### 播种三批 [DEFAULT]

本 skill 不写死任何项目的模块名。三批是方法，名单从**这个仓库的代码**现查。

1. **入口与一跳。** 找运行入口（AndroidManifest 的 launcher、`main()`、README 写明的启动类——以搜到的为准）。从入口类型搜跨包引用，登记入口拥有的下一跳。每行一个符号。
2. **主玩法。** 主玩法域 = 批 1 的边指向最多的业务包，**加上用户一句「主业务是哪些」**。每个主玩法域写拥有 + 进出边 + 不拥有。不是把套件作者记得的业务写进来。
3. **其余。** 工程已注册（Gradle `include`、顶层包、其它启动入口）但批 1/2 没覆盖的，写**薄细**：拥有（1～3 个类型）+ 至少一条进来或出去的边（带搜索）+ 一句不拥有。不准写成批 2 那种全表。真改到再加边。

skill 不准写死某项目名单。项目 INDEX 和详情从该仓库代码列名字，否则三批没法跑。不准三批一次点头。

### 总账模板（INDEX.md）

```md
# 架构总账 INDEX

> 每条一行：`[模块] 谁拥有什么（关键词簇 / 能搜的符号） → 详情文件`
> 只登记现状。本文件只是总账。检索以项目入口短契约为准；全文以 architect skill 为准。
> 模块行上限 40；超过按域拆，这里只留域名。

> 冷藏区：`archive.md`（死模块，未入索引，grep 可达）——暂无

## 模块
```

### 项目短契约模板（architect schema 1）

```md
## 架构检索（architect schema 1）

1. 任务开始读 `docs/architect/INDEX.md` 的索引行（写代码的任务不免除）。INDEX 只是总账，只登记现状。对上这次要动的模块 → 打开对应详情，并对该行符号做搜索。只扫标题、不打开 = 不算命中。
2. 代码与底图冲突，或命中行符号搜不到：按代码执行，底图不当场改，标「疑似过时」走自清洁问询。写入、删除、冷藏必须经用户确认。
3. 自清洁：即时——命中行搜符号，对不上当场问（未同意不得改 INDEX）；定期——每天首次 git pull 后按 architect skill 执行，写 `docs/architect/.last-clean`。跑不了就跳过并写明，不准假装已清洁。
```

## 可选连通 [DEFAULT]

- **输入：** 对话或仓库里已有需求规格，就当成本单要落地的目标；没有则先用一句话钉「改完谁能看见什么」。
- **方法：** 结构选项若像被「都这样 / 要做中台」带跑，可用 `first-principle-v2` 那套拆法。不是每次必用。
- **下游：** 本单结构可以被编码阶段当约束。编码仍以编码插件为主驱动。没有编码阶段时，交付仍然完整。
- **经验：** 有相关踩坑或难找入口则读。底图补丁不是经验条目。

单独用本插件不必写交接信封。只有明确要把上下文交给另一个插件时才写。

## 发生了还是假装 [INV]

同时成立才算发生：本单有归属；类图只覆盖碰到或新造的类型且每个点名有搜索格子；时序只覆盖这次调用且被调者有格子；INDEX 行有能搜的符号且未超 40（或已按域拆）；若归属变了则有底图补丁且问过用户；意图未当作现状写入 INDEX；项目没有底图时写明「未启用，不会被自动读到」。播种时：批 2 每个主玩法详情都有拥有 + 进出边 + 不拥有，否则播种没发生。已挂短契约的编码任务：扫了 INDEX 且命中行搜了符号。

下列算没发生：全仓函数调用图当底图；把细架构写进 INDEX；未同意就写 `docs/architect/`；代码和底图打架却改代码去迁就底图；只扫 INDEX 标题声称已按底图设计；请人点头时交不出搜索格子；把意图写进 INDEX；命中行不搜符号；skill 写死某项目名单。

## 死因 [DEFAULT]

连续 2 个月零使用 → 删除本插件。底图系统：你确认检索是负担或先停 → 降级为被动文档，去掉项目入口短契约（`docs/architect/` 可留着，但不再自动读）。两个月无补丁并且你确认不用了 → 短契约去掉，底图归档。

# architect — 架构师

本插件是套件定律的推论：系统怎么拆、这次改动落在哪，不进窗口等于没有。交付是结构，不是实现。底图只登记现状；意图只活在尚未落地的本单图纸。

规则分四级：**[INV]** 不变量（违反即缺陷，无豁免）；**[DEFAULT]** 默认策略（项目事实或用户要求可覆盖）；**[HEURISTIC]** 审查信号；**[EXAMPLE]** 示例。

编码任务不以本插件为主驱动。底图靠项目短契约进窗口（和经验同一机制）。用户要类图/时序/落点时，本插件才当主驱动。

## 硬规则 [INV]

1. **交付是结构。** 本单交付：模块/类型归属、本单类图（只画碰到或新造的）、本单时序（只画这次谁在什么时候调用谁）、对项目底图的补丁（若归属变了）。没有用户授权，禁止把设计当实现去改业务代码。
2. **底图写入、删除、冷藏必须经用户确认。** 起草可以；未同意禁止落盘、禁止改 `INDEX.md`、禁止偷改正文。
3. **代码与底图冲突：按代码执行。** 底图禁止当场偷改；标「疑似过时」并问。用户决策类（已拍的拆法）禁止进自动处理。
4. **未问、未同意，禁止改 INDEX。**
5. **底图只登记现状。** 禁止把「将来归谁」写进 INDEX。意图只活在尚未落地的本单图纸；代码合入后再补丁底图。
6. **底图海拔。** 现状底图：主模块和归属都在。禁止用全仓函数调用图当底图。本单图纸不到每个函数。
7. **格子能核对。** 本单类图每个点名的类型必须有搜索命中，或标「新造（已搜未命中）」。时序每个被调者必须能指出存在或标新造。INDEX 每一行必须有一个能搜到的符号。未交出这些格子，禁止请人点头。
8. **总账能数。** INDEX 模块行超过 40 则按域拆，总账只留域名。禁止一页全宇宙一次点头。播种分三批（见「播种三批」），每批最多 15 行且每行有搜索格子。skill 不准写死某项目名单。项目 INDEX 必须写从代码搜到的名字。
9. **没挂短契约则底图不会被自动读到。** 必须在交付里写明这一点，不准假装项目已经在用底图。
10. **命中要核符。** 打开某 INDEX 行时，必须对该行能搜的符号做搜索。搜不到则标「疑似过时」并问，禁止把死符号当活底图用。

## 何时出图纸 [DEFAULT]

会动模块归属、新类型、或跨块调用顺序 → 出本单图纸；归属变了则起草底图补丁。只改已有类型内部实现 → 读底图、不改底图。用户明确要类图/时序 → 出本单图纸。

## 底图 [DEFAULT]

家 = 每个项目的 `docs/architect/`。不进经验库，不进 skill 仓库，不进全局目录。

```
docs/architect/
  INDEX.md      # 总账：一行一个模块（现状）
  archive.md    # 冷藏（死模块）
  .last-clean   # 自清洁日期
  <域>.md       # 详情，命中才打开
```

**INDEX 是总账，不是细架构。** 细架构（拥有 + 进出边 + 不拥有）只活在详情文件。把调用顺序写进 INDEX = 假装。

**第一次（现状底图，不是意图）：** 已有代码走「播种三批」。还没代码：先出本单图纸（意图）；等有代码再登记底图。不准把设计图写进 INDEX 冒充现状。

**以后每一单：** 对着底图做本单类图和时序。意图与现状不同，写在本单图纸里，不改 INDEX。代码合入、搜索格子能打上之后，再交底图补丁。

## 检索 [DEFAULT]

存储不是约束，进窗口才是。

- 项目已挂短契约：每个任务开头扫 `INDEX.md` 索引行（编码任务不免除）。对上这次要动的模块 → 打开对应详情，并对该行符号做搜索。只扫标题、不打开 = 不算命中。命中 = 打开后会改变这次落点。
- 本插件主驱动时：读总账 + 打开本单相关块 + 交出搜索格子。
- 编码主驱动时：不切到本插件；短契约仍要扫 INDEX。
- 项目没有 `docs/architect/`：不建、不扫；用户明确要求启用才走播种。

## 自清洁怎么做 [DEFAULT]

真正防腐烂的是 INV 10：任务命中某行就搜该行符号。不靠 git hook，也不靠「记得 pull」。定期 pull 检查只是辅路径，跑不了就跳过。

1. 没有 `docs/architect/` → 跳过。
2. **即时（主路径）：** 打开 INDEX 行时搜该行符号。搜不到 → 候选「疑似过时」。
3. **定期（辅路径）：** 每天首次 `git pull` 后，用 pull 碰到的符号对 INDEX（约 3 分钟，写 `.last-clean`）。跑不了就跳过并写明，不准假装已清洁。
4. **问询：** 附证据和推荐（改 / 冷藏进 `archive.md` / 保留）。用户一句话裁决。未同意不动 INDEX。
5. 冷藏条目保持完整，grep 可达；模块复活时移回并恢复索引行。
6. 不装新 hook。经验那套 SessionStart 注入是另一条产品；底图靠短契约进窗口，靠 INV 10 核符。多一条 fail-open 钩子不会比短契约更真。

## 播种与 setup [DEFAULT]

会创建或修改项目文件。**[INV]** 只读任务禁止执行；未向用户明示将改的文件与内容并得到同意，禁止动手。默认不给任何项目播种。

1. 找入口（`AGENTS.md` / `CLAUDE.md` / 等效）。一个都没有时，只建 `docs/architect/`，并说明需要手挂短契约，否则总账不会被读到。
2. 建 `docs/architect/INDEX.md`（用下方总账模板）和空的 `archive.md`。
3. 按「播种三批」起草现状底图。每批 ≤15 行，每行一个能搜到的符号，用户点头后再写入详情并登记 INDEX。
4. 入口挂下方短契约（schema 1）。
5. 告知：底图已建或需手挂、从下个任务起生效。编码任务仍走项目已有编码插件；底图靠短契约，不切主驱动。

### 播种三批 [DEFAULT]

本 skill 不写死任何项目的模块名。三批是方法，名单从**这个仓库的代码**现查。

1. **入口与一跳。** 找运行入口（AndroidManifest 的 launcher、`main()`、README 写明的启动类——以搜到的为准）。从入口类型搜跨包引用，登记入口拥有的下一跳。每行一个符号。
2. **主玩法。** 主玩法域 = 批 1 的边指向最多的业务包，**加上用户一句「主业务是哪些」**。每个主玩法域写拥有 + 进出边 + 不拥有。不是把套件作者记得的业务写进来。
3. **其余。** 工程已注册（Gradle `include`、顶层包、其它启动入口）但批 1/2 没覆盖的，写**薄细**：拥有（1～3 个类型）+ 至少一条进来或出去的边（带搜索）+ 一句不拥有。不准写成批 2 那种全表。真改到再加边。

skill 不准写死某项目名单。项目 INDEX 和详情从该仓库代码列名字，否则三批没法跑。不准三批一次点头。
